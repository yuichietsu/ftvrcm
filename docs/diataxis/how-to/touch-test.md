# タッチ操作テストの使い方

設定画面から起動できる「タッチ操作テスト」画面で、注入された操作が正しく動作しているかを確認できます。

## 起動方法

設定画面 → **その他** → **タッチ操作テストを開く**

## 画面構成と確認方法

### 最終ジェスチャ（注入結果の可視化）

画面上部に「最終ジェスチャ: type / status (detail)」が表示されます。

| フィールド | 説明 |
|-----------|------|
| `type` | ジェスチャの種別（tap / double_tap / long_press / swipe / pinch_in / pinch_out / scroll_* 等） |
| `status` | `DISPATCHING` / `COMPLETED` / `REJECTED` |
| `detail` | 実行手段（例: `via=shizuku_input`, `via=FOCUS(true)+CLICK`, `via=SCROLL_UP`） |

### 1) ボタン（タップ / 長押し）

「ボタン A / B / C」をタップすると「最終イベント」に `ボタンX: タップ` が表示されます。
長押しが成立すると `ボタンX: 長押し` が表示されます。

### 2) リスト（選択・ダブルタップ・長押し）

- 単タップで `リスト: タップ (項目 N)` が表示される
- 長押しで `リスト: 長押し (項目 N)` が表示される
- ダブルタップで `リスト: ダブルタップ (項目 N)` が表示される（`GestureDetector` と連続クリックの両方で検知）

### 3) スワイプ / ズーム確認

| 確認項目 | 説明 |
|---------|------|
| 縦スクロール | ListView で上下スクロール |
| 上下左右スワイプ | スワイプ確認エリアで 4 方向のスワイプが成立するか確認 |
| ズーム | ズーム確認エリアでピンチイン/アウトが成立するか確認（倍率 $0.3\times$ 〜 $6.0\times$） |

## 各方式での動作の違い

### スクロール / スワイプキー

| 方式 | 動作 |
|-----|------|
| **Shizuku 方式**（デフォルト） | `IInputManager.injectInputEvent` でスワイプジェスチャを 0ms で注入。スワイプ距離は「動作チューニング」→「スワイプ距離（%）」で調整可能 |
| **AccessibilityService 方式** | `ACTION_SCROLL_*` を送出。最終ジェスチャの `detail` が `via=SCROLL_*` になるか確認する |

`ACTION_SCROLL_*` はジェスチャではなくスクロール命令のため、対象ビューによっては期待どおりに動かない場合があります。

### 「リモコン操作パススルー切り替え」

| 状態 | 説明 |
|-----|------|
| **カーソル** | 通常のタッチ操作（カーソルは輪っか表示） |
| **パススルー（方向キー）** | 割り当てられたタッチ操作キーを含め、リモコン本来の操作としてシステムに渡す（カーソルは DPAD 風アイコン表示） |

## 「最終イベント」が更新されないとき

以下を確認してください。

- AccessibilityService が有効になっているか（ステータスバーが「アクセシビリティ: 動作中」か）
- Shizuku 方式を使う場合、Shizuku が起動中で権限が付与されているか
- アプリが前面に表示されているか
- 端末側の制限（特定画面/システム UI への注入ブロック）がないか
